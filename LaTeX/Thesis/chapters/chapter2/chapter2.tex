در این فصل به آموزش مقدماتی زبان 
\eng{Haskell}
میپردازیم. در طول این فصل مباحثی از 
\eng{Haskell}
را بیان میکنیم که پیش نیازی از فصل های بعدی اند. این فصل دو قسمت است. در قسمت اول به آموزش زبان به صورت نظری میپردازیم و در بخش دوم از آموزه های بخش اول استفاده میکنیم تا تعدادی برنامه ساده بنویسیم. هر برنامه ای که در آن قسمت نوشته شود میتواند توسط خواننده نوشته و اجرا شود. 
\section{
مقدماتی از استاندارد زبان
}
یک شناسه یا 
\eng{identifier}
ار یک حرف و بعد از آن هیچ یا چند حرف، زقم، 
\eng{\_}
، علامت نقل قول مفرد 
\eng{\'}
باید ساخته شود. شناسه ها به صورت لغوی به دو فضای نام 
\eng{namespace}
تقسیم میشوند: آنهایی که حرف اول آنها کوچک برای متغیر ها و آنهایی که حرف اول آنها بزرگ است برای سازنده ها
\eng{constructor}
 هستند. بزای مثال سازنده 
\hs{Int}
برای ساخت عداد صحیح با حرف اول بزرگ مشخص میشود. نام گذاری باقی بخش های برنامه قوانین از پیش تایین شده ای دارند. این قوانین به تفصیل در
\href{https://www.haskell.org/onlinereport/haskell2010/}{\eng{Haskell Report 2010}}
بحث شده اند. لازم به ذکر است که کامپایلر
\eng{GHC}
که برای این گزارش استفاده شده، دارای توسیع هایی از این استاندارد است که تغییراتی جزیی در آن ایجاد کرده اند. تفاوت ها را میتوان در 
\href{https://www.haskell.org/ghc/}{\eng{haskell.org}}
در صفحه شناسه مربوط به هر نسخه کامپایلر دید.
\newline
نام گذاری در زبان 
\eng{Haskell}
به بزرگی و کوچکی حروف حساس است. به عنوان مثال
\hs{name}
، 
\hs{naMe}
و
\hs{Name}
همگی شناسه های متفاوتی هستند. به طور خلاصه اسامی توابع و متغیر ها باید با حروف کوچک شروع شوند اما بعد از آن برنامه نویس در انتخاب بقیه شناسه آزاد است.
\newline
در زبان 
\eng{Haskell}
میتوان از نوشتن نقطه ویرگول 
\hs{;}
و آکولاد
\hs{{ }}
صرف نظر و از تورفتگی یا 
\eng{indentation}
برای چیدمان برنامه استفاده کرد. وقتی از چیدمان استفاده شود باید قوانینی رعایت شوند؛ در غیر این صورت کامپایلر با برگرداندن خطا متوقف میشود. به صورت غیر رسمی در جایی که از آکولاد و نقطه ویرگول صرف نظر شده باشد مشابه پایتون است. فرورفتگی باید برای عبارات یک چیدمان یکسان باشند. برای مثال کد زیر را ببینید. این دو برش کد معادل هستند.
\begin{latin}
\begin{ghcode}
module AStack( Stack, push, pop, top, size ) where  
data Stack a = Empty  
             | MkStack a (Stack a)  
 
push :: a -> Stack a -> Stack a  
push x s = MkStack x s  
 
size :: Stack a -> Int  
size s = length (stkToLst s)  where  
           stkToLst  Empty         = []  
           stkToLst (MkStack x s)  = x:xs where xs = stkToLst s  
 
pop :: Stack a -> (a, Stack a)  
pop (MkStack x s)  
  = (x, case s of r -> i r where i x = x) -- (pop Empty) is an error  
 
top :: Stack a -> a  
top (MkStack x s) = x                     -- (top Empty) is an error
\end{ghcode}
\end{latin}

\begin{latin}
\begin{ghcode}

}};pop :: Stack a -> (a, Stack a)

  = (x, case s of {r -> i r where {i x = x}}) -- (pop Empty) is an error

\end{ghcode}
\end{latin}
\newline
توضیحات یا 
\eng{Comment}
ها همانطور که در بلوک های بالا میبینید مشابه زبان های برنامه نویسی دیگر رفتار میکنند. برای یک خط از دو  خط تیره و برای بیش از آن از نماد های 
\hs|{-|
 برای شروع بلوک توضیح و 
\hs|-}|
 برای پایان آن استفاده میشود.
\begin{latin}
\begin{ghcode}
-- This is a Haskell comment
----- So is this
{- Also 
        This
-}
\end{ghcode}
\end{latin}

\section{
انواع
}
در این قسمت به بررسی و معرفی انواع پایه ای داده در این زبان میپردازیم. 
\subsection{
انواع عددی
}
در زبان 
\eng{Haskell}
 انواع عددی اساندارد پشتیبانی میشوند. در این زبان انواع متعددی از اعداد صحیح و ممیزی ارایه شده اند.
\newline
در زبان هسکل دو نوع از اعداد صحیح توسط استاندارد تعریف شده اند. 
\hs{Int}
و
\hs{Integer}
نوع اول بازه محدودی از اعداد صحیح را پوشش میدهد. این بازه وابسته به تعداد بیت های اختصاص داده شده و وابسته به عللامت دار یا بی علامت بودن عدد است. در هسکل به صورت انواع علامت دار و بی علامت اعداد صحیح برای حالت های 8، 16، 32و 64 بیت تعریف شده اند. نوع دوم اعداد صحیح علامت دار با اندازه بی کران هستند؛ به این معنی که عدد صحیح نوع
\hs{Integer}
میتواند به هر اندازه بزرگ باشد. 
\newline
اعداد ممیزی در زبان هسکل از 4 نوع هستند.
\hs{Float}
،
\hs{Double}
، 
\hs{Rational}
و 
\hs{Scientific}
. اعداد 
\hs{Float}
از نوع 
\eng{Single Precision} 
هستند. 
 در مثال های زیر به بررسی نحوه تعریف این اعداد در محیط 
\eng{Glasgow Haskell Compiler interactive (GHCi)}
میپردازیم. این محیط در 
\label{sec:Appendix II}{
پیوست دو
}
به تفصیل معرفی شده.
\newline
برای اجرای این دستورات در 
\eng{GHCi}
لازم است دستور زیر را ابتدا اجرا کنید تا کتابخانه های مورد نیاز فراخوانی شوند.
\begin{latin}
\begin{ghcode}
:m + Numeric GHC.Float Data.Int Data.Word
\end{ghcode}
\end{latin}

\newline

\begin{latin}
\begin{ghcode}
ghci> floatRadix (1 :: Double)
2
ghci> floatDigits (1 :: Double)
53
ghci> floatRange (1 :: Double)
(-1021, 1024)
ghci> floatRadix (1 :: Float)
2
ghci> floatDigits (1 :: Float)
24
ghci> floatRange (1 :: Float)
(-125, 128)



\end{ghcode}
\end{latin}
در بلوک بالا اطلاعات کلی را درباره انواع 
\hs{Float}
و 
\hs{Double}
میبینیم. توجه کنید که تابع 
\hs{floatRange}
بازه نمای عدد ممیز شناور را خروجی میدهد. 
\begin{latin}
\begin{ghcode}
ghci> 0.1 + 0.2 :: Double
0.30000000000000004
ghci> 0.1 + 0.2 == (0.3 :: Double)
False
ghci> 0.1 + 0.2 :: Float
0.3
ghci> 0.1 + 0.2 == (0.3 :: Float)
True
\end{ghcode}
\end{latin}
در اینجا میبینیم که خطای نمایش اعداد
$0.1$
و 
$0.2$
در نوع 
\hs{Double}
خروجی باقی میمانند اما همین خطاها در نوع
\hs{Float}
در گردکردن پس از عمل جمع حذف میشوند. این با محیط 
\eng{Matlab}
 متفاوت است. در محیط 
\eng{Matlab}
همین عمل جواب دقیق و درست 
$0.3$
را تولید میکند. در نوشتن برنامه های عددی در زبان 
\eng{Haskell}
باید به این تفاوت ها توجه داشت. برای اینکه از رفتار عددی برنامه اطمینان حاصل کنیم بهتر است نوع هر عدد و بعضا خروجی هر عبارت را مشخص کنیم. در 
\eng{Haskell}
برای هر عبارتی که نوعش در برنامه مشخص نشده باشد توسط کامپایلر یک کلاس نوع یا 
\eng{Type Class}
مشخص میشود. این کلاس ها در بخش سوم همین فصل به تفصیل بحث میشوند. به طور خلاصه انواع در این کلاس ها دسته بندی شده اند. این تعریف آنهارا ساده تر میکند. اعدادی اعشاری که در برنامه تولید میشوند در کلاس 
\eng{Fractional}
قرار میگیرند. این کلاس انواع 
\hs{Float, Double, Rational}
دارد. تا زمانی که کامپایلر اطمینان حاصل نکند که کدام نوع را باید برای یک عبارت در کلاس 
\eng{Fractional}
 برگزیند عبارت "بدون نوع" مشخصی میماند. در حالتی که هیچ چیزی در برنامه برای کامپایلر نوع را مشخص نکند، کامپایلر از پیش فرض هایی برای انواع استفاده میکند. این پیش فرض ها در 
\eng{GHC's User Guide - 6.4}
آمده اند. با توجه به این موضوع بدیهی است که در برنامه های عددی باید اطمینان حاصل کنیم که نوع درست انتخاب شده، بنابراین بهتر است خودمان آنها را مشخص کنیم.
\newline
\begin{latin}
\begin{ghcode}
ghci> toRational (0.1 :: Double)               
3602879701896397 % 36028797018963968
ghci> decodeFloat (0.1 :: Double)              
(7205759403792794,-56)
ghci> showHex (castDoubleToWord64 0.1) ""      
"3fb999999999999a"
ghci> showHex (castFloatToWord32 0.1) ""       
"3dcccccd"
\end{ghcode}
\end{latin}
نوع 
\hs{Rational}
اعداد را به صورت اعداد گویای تحویل ناپذیر یعنی نسبت دو عدد صحیح از نوع 
\hs{Integer}
ذخیره میکند. لازم به ذکر است که این نوع اعداد گویا هستند بنابراین نمیتوانند برای نمایش اعداد گنگ استفاده شوند اما تقریب های دقیق تر از 
\hs{Double}
را میتوان در این نوع ذخیره کرد. در بلوک بالا میبینیم که عدد 
\hs{0.1 :: Double}
در نوع 
\hs{Rational}
با کسر

\begin{latin}
$\frac{3602879701896397}{3602879701896396}
\end{latin}
ذخیره میشود. این کسر گویا شده ی نمایش دودیی عدد
$0.1$
 در نوع
\hs{Double}
است. باید در نظر داشت محدودیت تبدیل مبنا در نوع 
\hs{Rational}
همچنان جود دارد. در خطوط بعدی بلاک بالا نمایش های مبنای 16 عدد $0.1$ را در انواع
\hs{Double, Float}
میبینیم. این ها دقیقا از قوانین 
\eng{IEEE 754}
پیروی میکنند. بلاک زیر تاییدی بر این مطلب است.
\begin{latin}
\begin{ghcode}
ghci> (isIEEE (1 :: Double), floatRadix (1 :: Double), floatDigits (1 :: Double), floatRange (1 :: Double))
(True,2,53,(-1021,1024))
ghci> (floatDigits (1 :: Float), floatRange (1 :: Float))
(24,(-125,128))
ghci> encodeFloat 1 (-52) :: Double
2.220446049250313e-16
ghci> 1 + encodeFloat 1 (-53) == (1 :: Double)
True
\end{ghcode}
\end{latin}
در خروجی اول از چپ به راست ابتدا خروجی تابع 
\hs{isIEEE}
را میبینیم. این تابع به ازای ورودی هایی که از استاندارد 
\eng{IEEE 754}
پیروی میکنند خروجی میدهد. این برای بسیاری از انواع استاندارد زبان صحیح است اما ممکن است برای انواع ممیز شناور تعریف شده در کتابخانه ها درست نباشد. سپس مبنای اعداد را میبینیم که برابر $2$ است، تعداد بیت مانتیسا و بازه نمای عدد نوع
\hs{Double}

. همه این مقادیر با استاندارد 
\eng{IEEE 754}
همخوانی دارند. در خطوط بعدی تعداد بیت مانتیسای نوع 
\hs{Float}
بازه نمای آن، اپسیلون ماشین و در نهایت بررسی اینکه آیا عدد 
$1 + \epsilon$
با یک برابر است یا خیر. 
\newline
در بلاک های زیر به بررسی بیشتر حساب ممیز شناور میپردازیم.

\end{ghcode}
\end{latin}
